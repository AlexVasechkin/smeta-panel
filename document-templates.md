# Шаблоны документов

Документ описывает хранилище шаблонов: как .docx попадает в S3, как размечаются
плейсхолдеры и что система о них знает.

## Главная идея

Шаблон — это файл Word с плейсхолдерами `{{ ... }}`. При загрузке он не просто
кладётся на диск, а **разбирается и переписывается**: система чинит разметку,
которую портит сам Word, и запоминает состав полей. На диск попадает уже
нормализованный файл, пригодный для подстановки.

| Что | Где лежит |
|---|---|
| Файл .docx | диск из `config/filesystems.php` (в проде — S3) |
| Карточка шаблона и состав полей | таблица `document_templates` |

Шаблоны не общие: каждый принадлежит одной организации (`organization_id`
обязателен). Чужой шаблон недоступен по прямому URL — 404.

## Разметка шаблона

### Одиночные поля

```
Договор № {{contract.number}} от {{contract.date}}
ИНН: {{org.inn}}
```

Одно значение на документ. Имя — латиница, цифры, подчёркивание, точка как
разделитель: `contract.number`, `org.inn`, `today`.

### Таблицы

Колонка повторяющейся строки помечается скобками `[]` после имени группы:

| № | Наименование | Кол-во | Цена | Сумма |
|---|---|---|---|---|
| `{{works[].num}}` | `{{works[].name}}` | `{{works[].qty}}` | `{{works[].price}}` | `{{works[].sum}}` |

В Word рисуется **одна** строка данных. При генерации она повторится столько
раз, сколько будет передано записей в группе `works`.

**Почему `[]`, а не просто точка.** Таблицами в Word сплошь и рядом верстают
макет — шапку письма, блок реквизитов. По одному лишь положению внутри `<w:tr>`
отличить колонку таблицы от обычного поля невозможно, поэтому признак
повторения задаётся явно. `{{org.address}}` внутри макетной таблицы останется
обычным полем.

Все колонки одной группы должны лежать в одной строке: повторяется именно
строка. Если колонки разъехались по разным строкам, парсер выдаст замечание.

## Нормализация при загрузке

`App\Support\DocxTemplate` переписывает файл, решая две проблемы.

**Разрывы между runs.** Word хранит абзац как набор `<w:r>` и легко рвёт
набранный плейсхолдер на части — из-за автозамены, проверки орфографии или
правки по живому:

```xml
<w:r><w:t>{{contr</w:t></w:r>
<w:r><w:t>act.num</w:t></w:r>
<w:r><w:t>ber}}</w:t></w:r>
```

Такой плейсхолдер не найдёт ни один подстановщик. Парсер склеивает текст
абзаца, находит плейсхолдеры и раскладывает текст обратно: плейсхолдер целиком
попадает в тот run, где он начался (и наследует его оформление), хвосты из
соседних runs удаляются. Символы вне плейсхолдеров остаются на местах, поэтому
смешанное оформление внутри абзаца не страдает.

**Пробелы внутри скобок.** `{{ works[].name }}` → `{{works[].name}}`.
Подстановщик сравнивает имя посимвольно, так что пробелы сделали бы плейсхолдер
другим. Набирать можно как удобно.

Обрабатываются `word/document.xml`, колонтитулы (`header*.xml`, `footer*.xml`)
и сноски (`footnotes.xml`, `endnotes.xml`).

## Замечания парсера

Замечания не блокируют загрузку — шаблон сохраняется, а список показывается
в карточке и помечается значком в списке.

| Ситуация | Замечание |
|---|---|
| `{{works[].name}}` вне таблицы | «находится вне строки таблицы» |
| Колонки группы в разных строках | «расположены в разных строках» |
| `{{works[]}}` без колонки | «задаёт таблицу без колонки» |
| `{{плохое имя!}}` | «содержит недопустимое имя» |
| Плейсхолдеров нет совсем | «не найдено ни одного плейсхолдера» |

Файл, который не является архивом или не содержит `word/document.xml`,
отклоняется как ошибка валидации поля `file`.

## Схема данных

Миграция `2026_10_30_000000_create_document_templates_table`.

| Колонка | Назначение |
|---|---|
| `organization_id` | владелец шаблона, `cascadeOnDelete` |
| `name`, `description` | карточка; `unique(organization_id, name)` |
| `disk`, `path` | где лежит файл; диск пишется в строку, чтобы переезд не ломал старые записи |
| `original_name` | имя при загрузке — отдаётся при скачивании |
| `size`, `checksum` | размер и sha256 нормализованного файла |
| `placeholders` | `{"fields": [...], "tables": {"works": [...]}}` |
| `warnings` | список замечаний парсера |

Путь на диске — `document-templates/{organization_id}/{ulid}.docx`.

## Маршруты

`routes/web.php`, внутри группы `middleware('auth')`:

| Метод | URL | Имя | Действие |
|---|---|---|---|
| GET | `/document-templates` | `document-templates.index` | список с поиском |
| GET | `/document-templates/create` | `.create` | форма загрузки |
| POST | `/document-templates` | `.store` | разбор и сохранение |
| GET | `/document-templates/{id}` | `.show` | карточка с составом полей |
| GET | `/document-templates/{id}/edit` | `.edit` | форма правки |
| PUT/PATCH | `/document-templates/{id}` | `.update` | сохранение, файл необязателен |
| DELETE | `/document-templates/{id}` | `.destroy` | удаление вместе с файлом |
| GET | `/document-templates/{id}/download` | `.download` | скачать .docx |

Пункт меню «Шаблоны документов» живёт в `mainNavItems`
(`resources/js/components/app-sidebar.tsx`).

## Фронтенд

| Файл | Назначение |
|---|---|
| `resources/js/pages/document-templates/index.tsx` | список, поиск, пагинация |
| `.../create.tsx`, `.../edit.tsx` | страницы загрузки и правки |
| `.../template-form.tsx` | общая форма + памятка по разметке |
| `.../show.tsx` | карточка: файл, поля, таблицы, замечания |

Правка уходит как `POST` с `_method=put`: PHP не разбирает multipart у `PUT`.
Пустой `file` при этом не отправляется — значит «оставить прежний .docx».

## Хранилище

Диск берётся из `config('filesystems.default')` и записывается в строку. Для
продакшена в `deploy/ansible/group_vars/all.yml` задаётся `filesystem_disk: s3`,
креды — в vault. `AWS_ENDPOINT` в шаблоне `.env` уже есть, поэтому подходит
любое S3-совместимое хранилище (Timeweb, Selectel, Yandex Object Storage), а не
только настоящий AWS: при непустом endpoint автоматически включается
`AWS_USE_PATH_STYLE_ENDPOINT`.

## Что дальше: генерация

Хранилище готово, подстановки ещё нет. План на следующий шаг — `phpoffice/phpword`:

```php
$tp = new TemplateProcessor($localCopy);
$tp->setMacroChars('{{', '}}');          // по умолчанию ${...}

$tp->cloneRow('works[].name', count($works));
// строка размножится, плейсхолдеры получат суффиксы:
// {{works[].name#1}}, {{works[].name#2}}, ...

$tp->setValue('works[].name#1', 'Демонтаж перегородки');
$tp->setValue('contract.number', 'Д-2026/14');
```

Колонка `placeholders` для этого и собирается: по ней видно, какие группы
размножать и какие поля ждать от источника данных. Расширения `dom`, `gd`,
`zip`, `xml` для PHPWord уже стоят и локально, и в Ansible-роли `php`.

## Памятка по подводным камням

1. **Скобки `[]` обязательны для таблиц.** Без них поле считается одиночным,
   даже если стоит в ячейке.
2. **Группа повторяет строку, а не ячейку.** Колонки одной группы должны быть
   в одной строке таблицы.
3. **Поиск по кириллице регистронезависим только на PostgreSQL.** Используется
   `ilike`; на SQLite (тесты) `like` различает регистр для не-ASCII — см.
   `likeOperator()`, тот же приём, что в справочнике организаций.
4. **Удаление файла не в транзакции.** БД и объектное хранилище нельзя откатить
   вместе: строка удаляется в транзакции, объект — после успешного коммита.
   Худший случай — осиротевший файл в бакете, а не битая карточка.
5. **Нет версионирования.** Загрузка нового файла заменяет прежний и удаляет
   старый объект. Если понадобится история — это отдельная таблица версий.
6. **Нормализованный файл отличается от загруженного** побайтно: `checksum`
   считается уже после правки, и скачанный файл не совпадёт с исходным.
